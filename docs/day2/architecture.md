# Архитектура программного модуля — Мобильное приложение «Заметки»

## 1. Архитектурные слои
Приложение спроектировано по принципу разделения ответственности на три независимых слоя в пакете `com.example.a1_2day`:

1. **Слой представления (UI):** отвечает за отображение данных и взаимодействие с пользователем (`MainActivity`, `NoteDetailActivity`, `NotesAdapter`). Не обращается к SQLite напрямую.
2. **Слой бизнес-логики (Repository):** содержит правила валидации, сортировки и фильтрации заметок (`NoteRepository`). Зависит только от абстрактного интерфейса `NoteDataSource`.
3. **Слой данных (Data):** определяет модель данных (`Note`), контракт хранилища (`NoteDataSource`) и его конкретную реализацию на SQLite (`DatabaseHelper`).

Выделение интерфейса `NoteDataSource` позволило полностью отвязать бизнес-логику от Android SDK и обеспечить возможность быстрого модульного тестирования с использованием подмены хранилища в памяти (`InMemoryNoteDataSource`).

## 2. Структура пакетов (`app/src/main/java/com/example/a1_2day`)
- `MainActivity.kt` — главный экран со списком заметок, живым поиском и кнопкой создания;
- `NoteDetailActivity.kt` — экран создания, просмотра, редактирования, удаления и экспорта заметки;
- `ui/NotesAdapter.kt` — адаптер `RecyclerView` для отображения карточек заметок;
- `repository/NoteRepository.kt` — бизнес-логика, валидация и поиск;
- `data/Note.kt` — модель данных заметки;
- `data/NoteDataSource.kt` — интерфейс источника данных;
- `data/DatabaseHelper.kt` — реализация локального хранилища на базе `SQLiteOpenHelper`.
