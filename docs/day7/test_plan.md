# Тест-план и модульное тестирование (День 7)

## 1. Объект и окружение тестирования
- **Объект тестирования:** мобильное приложение «Заметки» (пакет `com.example.a1_2day`, версия 1.0).
- **Тестовое окружение:** Android Studio, эмулятор Android (API 34–36) / физическое устройство Android (`minSdk 24`), JVM (JUnit 4.13.2).
- **Виды тестирования:** функциональное тестирование методом «чёрного ящика», проверка граничных значений (пустой ввод, пробелы, длинный текст, перезапуск), модульное тестирование слоя бизнес-логики.
- **Критерии приёмки:** успешное прохождение всех тест-кейсов базового функционала и 100% прохождение unit-тестов; отсутствие открытых дефектов уровня `Blocker` и `Critical`.

## 2. Модульное тестирование (Unit-тесты JUnit4)
В файле `app/src/test/java/com/example/a1_2day/NoteRepositoryTest.kt` реализованы 5 независимых модульных тестов на фреймворке JUnit4. Для изоляции от Android SDK и SQLite создан фейковый источник данных в памяти `InMemoryNoteDataSource`, реализующий интерфейс `NoteDataSource`:

- `testAddNote_success` — проверяет успешное добавление заметки, генерацию ID > 0 и сохранение полей.
- `testAddNote_emptyValidation_throwsException` — проверяет выброс `IllegalArgumentException` при передаче строк из пробелов и переносов.
- `testUpdateNote_success` — проверяет корректное обновление заголовка и содержимого существующей заметки.
- `testDeleteNote_success` — проверяет удаление записи и возврат `null` при повторном запросе по ID.
- `testSearchNotes_caseInsensitive` — проверяет регистронезависимый поиск по заголовку и тексту среди нескольких заметок.
